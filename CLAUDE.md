# music-video-pipeline

Python orchestrator that turns a master audio track + lyrics file + cast reference photos + a narrative concept into a complete, lip-synced music video by driving a local ComfyUI instance running MiniMax H3.

## Source-of-truth documents

- `comfyui-setup-summary.md` — the *actual* state of the ComfyUI install on doris (versions, model files, limitations).
- GitHub issues #1–#19 — the work breakdown. Issue comments contain reality-check corrections to the original bodies; read the comments, not just the body.

## Architecture (5 stages)

1. **Forced alignment** — `stable-ts` `model.align()` maps audio to the lyric text with word-level timestamps (`suppress_silence=True` VAD, `regroup=True`). `alignment_quality.py` scores the result and logs a summary at INFO on every run; `strict_alignment` turns a critical finding into a refusal. Alignment is ~6 s on CPU and a render is hours — always re-align and read the summary before spending GPU time.
   - **Which whisper model is config, and it decides how much of the song gets sung.** `alignment_model_size` (default `"base"`, so every pre-existing config is unchanged) is plumbed to all **three** `align()` call sites — `run_pipeline`, `prepare_shot_plan`, and `authoring/chunks.py`. On "Deathless" (8:32) `base` found 77.2 s of vocal and believed the singing stopped at 3:11, which would have rendered 56 of 71 chunks as "performs silently" over a master that has her audibly singing — no error anywhere. `small` found 187.2 s and ran to 8:21. **Bigger is not better by default:** `medium` placed a lyric 17 s before any vocal energy exists and dropped closing-refrain segments into the trailing silence, the same hallucination #42 recorded on "The Lucky Ones". Measure per song; the #35 quality report is the instrument, and it *did* flag this (20 critical findings, `track_confidence_collapse` at 69% of words below 0.10) — what was missing was any lever to act on it.
2. **Temporal slicing + prompt expansion** — `pydub` slices per-segment audio stems (4–15 s window, pad/merge below min, split above hardware max); prompt = Global Style + Narrative Concept (or this chunk's shot-plan line) + active cast member role + literal lyric line. A voiced chunk's **start** is then preferred at its own first prompted word's onset (#79, always on), by a compensated grid-step transfer across that one boundary — so this pass moves chunk boundaries relative to any plan authored before 2026-08-16, and such a plan must be re-anchored with `--prepare`, not re-anchored from itself.
3. **Asset staging** — upload cast images + audio stems to ComfyUI `POST /upload/image` (multipart; it ingests audio too); the *server-returned filename* is what goes in the workflow payload.
4. **Execution** — mutate `workflow_api.json`, `POST /prompt` with a UUID4 `client_id`, monitor via WebSocket, fetch output through `/history/{prompt_id}` + `/view`.
5. **Assembly** — FFmpeg concat demuxer (`-c:v copy`, never re-encode), strip ALL generated audio, mux the pristine master track over the video.

`--prepare` runs Stages 1–2 only (no GPU, no ComfyUI, no custody handoff) and writes a `shot_plan.toml` skeleton with `chunk_id`/`start`/lyric filled in and `shot` left blank (issue #52) — the anchors a shot plan is authored against, and the two things a generator must never invent. `--prepare --from-plan <plan.toml>` reads an existing plan **for its `length_seconds` only** and re-anchors the skeleton against the timeline a render with those lengths actually produces; without it, any plan setting a length describes chunks no render will emit and raises `ShotPlanDriftError`.

## Authoring layer (issue #54, all four phases landed)

`music_video_maker/authoring/` + the separate `mvm-author` console script propose a narrative concept, a beat sheet, the photography, and the shot lines — ending in a `shot_plan.toml` a human reviews and commits — through the Claude CLI, the one place in this project that is allowed to call a model. Validated 2026-08-13 by re-authoring "The Lucky Ones" from scratch against the real CLI. A 3-chunk validation slice of that plan (`run_v9.toml`, chunks 4/26/29) was rendered the same day — issue #58's findings — and it is the only part of a generated plan that has been rendered; **the full 36-chunk render has not.** Strictly outside the 5 stages above: no GPU, no ComfyUI, no custody handoff, and its output is a JSON/TOML file a human reviews and commits, never something read back into a render automatically. The render/authoring import boundary is enforced mechanically, not just documented — see `tests/test_authoring_boundary.py` and `music_video_maker/authoring/__init__.py`'s docstring.

- **Stage 2's value is that it is checkable, not that it writes well.** `beat_role`/`beat_group` make three of `docs/shot-writing-guide.md`'s checklist items machine-checkable *before* any prose exists (a consequence needs an earlier plant and contact in its own group; a consequence needs `focus = "action"`; a lone consequence is a cause and its effect in one shot). Every problem is reported in one message, because a retry round costs a whole model call.
- **A generated anchor is never trusted.** `chunk_id` is matched against the skeleton and anything else is dropped; `start`/`end` are re-emitted from the skeleton every time. That is what makes drift structurally unreachable for a generated plan, rather than merely unlikely.
- **A `length_seconds` re-cuts the timeline, so beats re-anchor by song time.** `authoring/reanchor.py` maps each beat to the chunk containing its midpoint — never by chunk id, the same rule `ShotLength` follows. Getting this wrong raises nothing; it silently attaches shot 12's direction to shot 9's audio. A chunk no beat maps into goes back to the model, never left blank — blank falls through to `narrative_concept` and renders as something deliberate-looking nobody authored.
- **Staleness cascades through the input hashes, not a dependency graph.** `beats` hashes the concept it descended from and `prose` hashes the beats, so re-rolling an upstream stage reports the downstream one stale by the same comparison that catches an edited lyrics file. Reported, never auto-healed.
- **A generated plan is checked by the render's own loaders, never a copy of them.** `plan.check_plan` writes the candidate to a temp file and runs `load_shot_plan`, `shot_length_requests`, `resolve_shot`/`resolve_camera` and `lint_shots_against_lyrics` with a log handler attached. Those lints encode measured lessons; a second implementation drifts within a month.
- **Errors and warnings are two tiers on purpose, and asymmetric.** Errors get a targeted revision of the offending chunks, bounded at 2 rounds, then abort with nothing written. Warnings get exactly one round — written as a single `if`, not a bounded loop, so there is no number to tune upward — and survivors are annotated into the file as `# lint:` comments. Every one of these lints is documented as "a false positive must never block a run"; a loop that grinds them to zero will rewrite a correct shot to please a heuristic.
- **A targeted revision must return only what it was asked to change.** `prose.revise_prose` shows the model the whole beat group so the rewrite stays coherent, but validates against the objected chunks alone and returns only those; merging is the caller's. A retry that quietly rewords thirty approved shots destroys the value of the approval before it.
- **A lint that guesses loses to a stage that knows.** `_lint_consequence_focus` infers "this reads like a consequence" from keywords; the beat sheet has the answer. On the first real run the keyword lint fired on four chunks the beats stage had called plants and transitions, they went into the revision round, and the rewrite put "She" back into the subject slot of lines that had correctly led with the object. Where structure contradicts the heuristic, structure wins and no objection is raised.
- **Every stage that writes must see `global_style`.** It is the junk drawer #53 split up, so it carries editing and camera constraints ("ONE continuous unbroken take, no cuts") and it is composed into every rendered prompt regardless. A photography stage that has not seen it proposes locked-off frames for a run whose style says the camera follows her.
- **Anchors are copied from the chunks at every layer.** Stage 2 re-emits `start`/`end` from the skeleton, and `render_plan_toml` takes them from the frozen timeline, not from the beats. Both `prose` and `write` then re-slice and *verify* the beat sheet's anchors still match before doing anything — `ShotPlanDriftError` caught where re-running a stage is the cheap fix, not hours into a render.
- **Grammatical subject is necessary but not sufficient (issue #58).** The v9 validation slice put a printer in subject position for both its plant and payoff beat, exactly as `docs/shot-writing-guide.md` asks, and H3 rendered neither — both lines also staged it small and far away ("small against the tower far behind her", "far behind on the street"). A third beat in the same slice, staged near and large, rendered correctly. `docs/shot-writing-guide.md`'s "Stage the object near, not far" and `shot_plan._lint_distant_staging` are the fix; `prompts.PROSE_PREAMBLE` carries the same rule. Confirmed by hand-editing chunks 4 and 29 to stage the printer near and re-rendering: both produced the printer for the first time, on the second try.
- **A generalisation from one chunk is a hypothesis; the full render is the experiment (#60).** #58 made `focus = "action"` on a voiced chunk the primary face-away signal, generalising from a single chunk re-rendered three times. The first full 36-chunk render tested it on 7 at once: all 7 turned away as predicted and **all 7 kept their lip-sync**. The mechanism was real, the predicted cost was not. The one chunk that did lose sync was a `transition` beat with `focus` unset whose *prose* did the same job — "Behind them, ... as they keep walking". So the lint was wrong in both directions at once, and the predictor lives in the sentence, not the field. Its replacement keywords were **scored against those 36 real lines before shipping**: "keep walking"/"behind them" match only the true positive, "receding" was excluded because it matches a chunk that synced fine, and bare "behind her" was excluded because it is in 20 of 36 lines that were all correct. Pick lint keywords by measurement on a corpus with a known outcome, and record the *excluded* candidates with their reason.
- **A realism LoRA and a flattering `appearance` are not both satisfiable (#62).** The fal H3 realism adapter at strength 0.8 costs ~1.5% wall clock and does make faces more photoreal — and it fights `global_appearance = "flatteringly lit"` and a de-aged `appearance` band, because those ask for the opposite of realism. Consistent with the adapter's own metadata (`training_strategy: text_to_video`, `first_frame_conditioning_p: 0.0` — it has likely never seen the reference-image conditioning `appearance` exists to modulate). Not a defect: a run must decide whether it wants photoreal faces or flattering ones, and asking for both means the stronger signal wins silently. Measured as a proper A/B — two configs identical but for three lines, separate output dirs, `lora`/`lora_strength` in the fingerprint's inescapable tier so a resume cannot mix arms.
- **A prohibition can cause the bug it was meant to prevent (#59).** `PROSE_PREAMBLE` forbids naming a cast member in a shot line — correctly, since the render composes names itself — which leaves a pronoun as the only way to refer to a second character. 9 of 36 generated lines said "him"; on the 7 where he was not also the singer, nothing bound the pronoun to anybody and H3 invented a different man each time. `chunk.characters` answers "who is *singing*" (the alignment knows that); `ShotPlanEntry.present` is what answers "who is *on screen*", and it carries role, appearance and reference photo into the prompt. Same shape as "a property that must hold needs its own field", one level down: free text in `shot` resolves against nothing.
- **On a sung chunk, the sentence's action belongs to the singer — `present` is not that lever.** #59 added `present` so a pronoun binds to a cast member instead of H3 inventing a stranger, and it works: measured on "Deathless" chunk 7, Jan rendered as Jan, hat and glasses and purple shirt, from his `role` text. But `present` decides *who a pronoun is*, never *whose shot this is*. That chunk's line gave the action to him ("...as he stands high above it on the mountain's edge, watching") on a chunk Dianne sings throughout, and he held frames 0–101 of 175 — she got the last 41%. Removing `present` was worse, not better: she *inherited* the watching, turned her back to camera, and **0 of 35 sampled frames contained a detectable face** (`faces.detect_faces`, the same YuNet the #47 gate uses). Both settings lose the sync; the fix is the sentence. `PROSE_PREAMBLE` rule 11. Same shape as #60 — the predictor lives in the sentence, not the field — one level up.
- **A plan that sets `length_seconds` has two timelines, and only one is real.** Diffing a generated plan against a skeleton built *without* `--prepare --from-plan` will show it "missing" chunks it was never supposed to have: on "Deathless" the plan's own lengths collapsed 6 chunks into 2, so the 80-chunk natural skeleton described chunks no render would emit, and a 79-entry plan looked one short. It was complete. The check that settles it costs 50 s and no GPU. `ShotPlanDriftError` is what catches this if you act on the wrong count — it refused a run and named the discrepancy in seconds (`authored against start=460.333s but this run's chunk starts at 458.917s`) before any GPU work, on an authoring error a human review of the plan could not have seen, because the plan *looked* complete.
- **`write`'s lint revision round can undo a deliberate instruction.** A targeted `prose --groups N --notes ...` reworded 10 sung chunks so the singer performed the action; `write`'s warning round then rewrote 5 of them straight back to the other character, because the she-focused versions tripped the distant-staging and consequence-focus heuristics. This is the documented risk arriving in practice — "a loop that grinds them to zero will rewrite a correct shot to please a heuristic" — and the reason the round is one pass, not a loop. When a measured finding and a heuristic disagree, the finding wins and the merge is the caller's: restore those lines from `.authoring/prose.json` by hand.
- **A shot line may not refer to another shot (#61).** Each chunk renders from its own prompt, by a model that has never seen any other shot. "The printer teeters on the sill of *that same empty frame*" pointed at a window broken two chunks earlier and rendered no printer at all, while the shots either side rendered theirs. `_lint_anaphora` and `PROSE_PREAMBLE` rule 10; re-describe every object in full, every time.
- **A voiced consequence chunk's lip-sync loss is not a wording problem.** The v9 slice's one working consequence shot left her back-to-camera for most of a chunk carrying a real lyric line. Three follow-up re-renders of that exact chunk each changed one thing — two rewrites of `camera`, one rewrite of `shot` to stop her walking and say she was still facing the lens — and all three still turned her away by roughly the shot's midpoint. The one thing held constant across all three failures was `focus = "action"`, which is what hands the sentence's subject to the consequence in the first place. The fix isn't camera wording (tried three times, failed three times); it's `prompts.BEATS_PREAMBLE` steering a `consequence` beat onto a nearby INSTRUMENTAL chunk when one is available. **Superseded in part by #60 above — read that first.** The camera-wording finding stands, but the `focus = "action"` lint built on it did not: the full render showed turning away is common and usually costs nothing, so that check is retired and `focus = "action"` on a voiced chunk is no longer something to avoid.
- **A lint shipped on a partial corpus is a hypothesis that has stopped announcing itself (#76).** `lint_voiced_framing`'s keyword sets were scored mid-render and did not survive the finished one: measured over the 41 voiced chunks, `_GAZE_AWAY_KEYWORDS` scored 0.72x (justified at 3.5x when it shipped), `_FOOT_LEVEL_KEYWORDS` 0.99x — indistinguishable from noise — and the one set that separates, `in profile` at 0.41x with no counter-example, is the one that was measured and *rejected* at n=3. This is #60's own lesson one level up, and the correction is asymmetric: retiring foot-level lost a true positive (chunk 22, 33%) to remove a false one (chunk 68, 92%), which is a trade, not a win, and is recorded as one. The corpus and every score now live in `docs/deathless-render-corpus.md` so the next revision starts from data; the "does the camera clause name the face" replacement hypothesis was tested there at n=41 and came out **backwards** (named 50.8%, not-named 59.8%), so it is dead rather than pending.
- **`present` binds a name, not a referent (#72).** Chunk 65 sets `present = ["Dianne"]` on a chunk Dianne already sings, so it binds nothing that was not bound — while the line's `he`/`his` points at Jan, who is in no field at all, and H3 invented a statue. The #64 lint checks a property of the *prompt* ("is some cast member present?"); the property that matters is a property of the *sentence* ("does every pronoun resolve to a cast member the prompt carries"), and those coincide only when the shot mentions exactly one person. Confirmed on pixels: chunk 66 is the mirror case, and its rendered frames show a dark cloaked figure who is not Jan (no hat, no glasses, no purple shirt). `CastMember` has no gender field, so the issue's proposed gender-mismatch check was not buildable; the structural version that shipped needs none and fires on 2 of 80 with no false positives.
- **A prohibition has no channel to be enforced in (#73).** "never holding anything" in `role` was in force for the entire render and put a bass guitar in his hands twice. Two reasons, and the second is architectural: negation is unreliable generally, and `MiniMaxH3ReferenceToVideo` exposes exactly one `prompt` input into a single `BasicGuider` — there is **no negative-conditioning channel** the way an SDXL-style graph has, so there is nowhere for "not this" to go. The concept stage's `avoid` list, orphaned since F13, now reaches the render, but it inherits the same limitation and says so in its own docstring. Say what IS true ("empty-handed, hands at his sides"); the durable check is a lint catching a shot line that contradicts the prohibition, not the prohibition itself.
- **Demeanour needed its own field, and the reference photo was deciding by default (#74).** `role`, `appearance` and `global_appearance` said nothing about expression, so a smiling reference photo carried eight and a half minutes of a video about massacre. `CastMember.demeanour` + `global_demeanour` compose into every prompt like `appearance` — with two deliberate differences: demeanour is **not** stripped on the chained I2V variant, because it is behavioural direction like `role` rather than a photo description, and it must state an endpoint ("grave, unsmiling") never a displacement ("less cheerful"), which is #46 one field over and is now a validation warning.
- **Every alignment check reasoned about timing and text; none asked whether there is a voice there (#71).** `small` placed the closing refrain 12 s into the fadeout and *everything* passed — `isolated_segment` (12.18 s gap against a 20.0 s constant), word confidence, the whole quality report, and human review of the plan, which read perfectly well. #42's proposed cross-model disagreement would have waved it through too, since `small` and `medium` agree within two seconds *on the phantom*. The check that separates it compares each placed segment's >3.4 kHz consonant-band share against the track's own median: the phantom sits at 2% of baseline where every real vocal window is 17% or more. Self-calibrating per track, so no absolute threshold — and it fires on the real case with no GPU.
- **Absolute darkness is the statistic; drift is not (#77).** F11 proposed a +/-15 Y start-to-end band from a 3-chunk slice. Across all 80 chunks, 36 fall outside it, ranging -61 to +55 — because a song whose narrative is a night ending in dawn has large luminance swings as its *content*. What isolates the authored fade-to-black over a sung line is the floor: chunk 43 ends at Y 14.9 and the next darkest ending anywhere is 36.4. The proposed authoring-side lint for it did **not** ship, because the measurement does not support one: "goes dark"/"dims" match only chunk 43 (n=1), "fading" is a measured false positive, and "dawn" appears on 9 chunks trending toward *brightening*, so it would fire backwards on this song.
- **A boundary that splits a sung phrase mostly is not made by the code that looks like it makes boundaries (#70).** 26 of 80 chunk boundaries landed inside an aligned segment. The max-duration split only ever sees 7 of them; `_cover_instrumentals`' own grid-quantized re-anchoring moves every one of those and introduces 15 more, 27 in total. Segment edges are now preferred cut points in the split that can honour them, and — the part that bit first — a snap is only accepted if `clamp_to_trained` did **not** relocate it: checking the duration *after* clamping is vacuously true whenever `eff_min` sits at the trained floor, which is the real production profile, so the first version logged six snaps that every one of them silently landed back inside the segment it claimed to avoid. Biasing instrumental tiling is **not** done: contiguity (video offset == audio offset by construction) is the invariant that makes the whole timeline correct, and it is not worth trading for lip-sync without a render to verify against. All 27 are now logged at their final position instead. **#70 was closed unfixed on 2026-08-16 and should stay closed.** A viewer's notes on the second full render named four sync failures and three of them are not this mechanism at all — they are chunks that *begin* in a vocal gap, where the mouth starts at frame 0 and is out of phase for the whole chunk (#79). The leading edge explains more of what a viewer actually notices, is a smaller change, and is verifiable with `--prepare` alone. If this is ever revisited, do not start by editing `_cover_instrumentals`; start by asking whether fewer, longer chunks (#27's `shot_lengths`) removes the boundaries instead of moving them.
- **`demeanour` is a framing lever wearing an expression label, and its strength scales with how much face it names (#74, measured 2026-08-16).** It fixes what #74 filed — the reference photo's smile carrying a war video — and it also doubled face presence across the whole render: 29.2% → 59.1% mean over 80 chunks, chunks with no detectable face 43 → 13. Not the `present` edits: the 71 chunks untouched by those moved just as much (31.1% → 59.4%, 45 up vs 11 down), which is not a seed pattern. Three arms at identical seeds on chunks 54/67/61: `"grave and hollowed out, mouth set hard, eyes tired and unsmiling"` → 100/100/100%; `"grave, weary and unsmiling"` → 83/0/33%; absent → 0/0/0%. Same mechanism as the `avoid` finding one bullet down, from the opposite direction — H3 renders the nouns it is given, so **naming a mouth and eyes puts a camera on them**, silently overriding shot lines authored as wide landscapes. Write demeanour as *manner* ("grave, weary, unhurried"), not as facial anatomy, unless close framing is what you want.
- **A prohibition with no channel to live in manufactures what it forbids (#73, measured 2026-08-16).** The concept's `avoid` list was wired into every render prompt on the reasoning that "something composing it beats nothing composing it, and it is strictly additive". It is additive — *of the forbidden nouns*. Single-variable A/B at an identical seed, one clause different: on "Deathless" chunk 72, whose shot has no climbing in it and whose character's `role` has no climbing in it, `avoid = [..., "modern climbing equipment, ropes, harnesses or safety gear"]` rendered a full climbing harness, carabiners and a trailing rope on him; without it, plain trousers, framing and background otherwise identical. On chunk 53, where she is already climbing on a rope, the same clause changed nothing — so the damage lands exactly where the prohibition has nothing to suppress, and a one-chunk test reads it as inert. `MiniMaxH3ReferenceToVideo` has one `prompt` input into a single `BasicGuider`: there is no negative-conditioning channel, so a prohibition cannot subtract. Removed from the render path; the authoring-side `avoid` (a model reading English) is untouched and still useful. This is the same shape as "never holding anything" one level up — and note the first uncontrolled comparison pointed the *opposite* way on chunk 53, which is why the A/B is not optional.

- **A place label names a place *at a time*, and `location`'s vocabulary is enumerated before the events that split it exist (#78, measured 2026-08-21).** The concept stage emits `locations` as a flat list, so a place that survives a world-changing event has a before-state and an after-state and only one label. On "Deathless" it happened to emit after-variants for the summit and the island — the lyrics name those changes — but not for the mill, whose destruction the *beats* stage invents later at chunk 62. The two act-5 chunks set at the mill therefore carried act 1's tag verbatim and rendered a sunlit English mill (green trees, hedgerow, mown grass, an intact-looking wheel) twenty seconds from the end of an act called "the silent planet". 15 of act 5's 17 chunks had been moved onto an after-tag by hand; these two were missed and were the worst two in the act. `authoring.worldstate.check_location_tags` catches it **structurally, with no vocabulary at all** — correct authoring is two labels either side of the event, incorrect is one label spanning it — firing on exactly those 2 of 80 with zero false positives and going silent once fixed. Confirmed on pixels at an identical seed, `prompt_hash` the only fingerprint field differing: vegetation 6.21% → 0.00% and 4.27% → 0.07%.
- **An adjective in a shot line qualifies the noun it attaches to; the location clause governs the frame (measured 2026-08-21, n=2 — a hypothesis).** The same burnt-valley clause, in the idiom that worked on four earlier chunks, took chunk 73 down 81% and chunk 74 **up 144%** — adjacent chunks, one location tag, one singer, identical seeds. The frames show the near slope burnt black and the distant valley greener than before: the phrase burns the ground it points at and leaves the rest to default. Both chunks already carry the correct after-tag, but it names *where the camera stands*, not the second place a wide shot from a summit puts in frame — so the distance is outside every field and H3 fills it with farmland. **An edit that produces opposite outcomes on two adjacent chunks is not a lever, whatever it did on the four before it**; chunk 74's was reverted to the wording that measured better, and act 5's largest remaining defect is now that distance.
- **`location` names where the camera stands, not what it overlooks — and the *shorter* tag wins (measured 2026-08-22).** A summit shot's far ground is most of its frame and was described by no field at all, so H3 filled it with farmland while the near slope obeyed the burnt clause. Measured before it was fixed, at n=8 with a control: act-5's stray vegetation sat **7.0x** upper-weighted (centroid 0.388) where legitimately-green earlier chunks sat at **0.9x** (centroid 0.520, evenly spread) — a claim about frame position, testable on pixels already rendered with no GPU. Naming the far place *inside* the same tag fixed it (act-5 mean 0.219% → 0.029%; chunk 74's upper half 3.58% → 0.00%), and the two-arm A/B is what made it a finding rather than a guess: the arm that **replaced** the do-nothing sky clause (79 → 86 chars) beat the arm that **added** to it (79 → 114) on every axis, including leaving the regression control untouched. #32 is real and arrives as length; a single long arm that worked would have shipped with the length credited as harmless. Verify on pixels either way — a clause that out-competes the shot line also produces zero vegetation, by replacing the shot.
- **Nothing tracked where the characters were, only where the world was (#78).** `setting` (#32) anchors the world's contents and works; it says nothing about where each character stands inside it at a given moment, which is how a plan came to put the mill in the valley below at 0:54 and at her shoulder at 1:32 with every line between describing ascent. Because #61 forbids a shot referring to another shot, something other than the shot lines has to hold continuity — so `location` is enumerated by the concept stage, assigned per beat, and checkable before any prose exists. The prose-side landmark-contradiction lint took three narrowing passes to ship: matching any repeated word plus a bare "below" fired on ~32 pairs, nearly all because a distance phrase attaches to a *different* noun in the same sentence than the shared landmark. Restricted to `setting`'s own vocabulary, with phrases specific enough not to misattach and a 60 s window, it fires on exactly the one true positive.
- **The lyrics were handed over as text to *stage*, never as text to *understand* (#69).** `build_concept_prompt` gave the model the lyric text, the skeleton, the cast and the fixed style, then asked for a video — so the concept stage invented a video for a song nobody had asked it to read. The fix is a *question*, not an instruction, and no amount of preamble tuning substitutes: a required `reading` object on the concept reply (subject; speaker and addressee; situation and what changes; register, period and place; the concrete nouns the lyrics themselves name; and `references`, each with its own imagery), filled first and composed into the beats prompt so it is consumed rather than merely recorded. `--tools ""` is untouched — the model already knew who Koschey was; nobody asked. **Empty is a first-class answer** and is validated as one: a model required to produce a mythological reference for a breakup song will invent one, and the invention gets staged. The example proves the bug; it does not define it — a fix scoped to folklore helps one song in fifty and looks finished.
- **Nothing owned the arc, so nothing could notice its absence (#84).** `beat_role`/`beat_group` make any three adjacent beats coherent; there was no field and no check at the scale of the whole video, so 80 shots passed every lint and were still a sequence of events. Asking a preamble for "a story with an arc" is the version that feels like it works and cannot be verified — the beats stage's value was never that it writes well, it is that its output is *checkable*. So: the concept emits a closed, ordered `acts` vocabulary (chosen per song — a ballad and a protest song do not have the same shape), every beat carries exactly one `act`, and four mechanical checks run — every act non-empty, acts in the stated order, each act's beats one unbroken run, and **the final act contains a `consequence` whose `beat_group` also holds a `plant` in an earlier act**. That last one is the only real test of an arc and it is already expressible in the vocabulary the stage had.
- **When a required participant is missing, the code substituted a config default — and a default chosen to answer a different question silently answered this one (#82).** `chunk.characters` answers "who is singing"; on an instrumental chunk it is empty, so `prompting` fell back to `default_lead_vocalist` and composed that person as *"is the focus of this shot"*. On "Deathless" chunk 29 the shot line was entirely about Jan, the prompt billed Dianne as the focus and Jan as a bystander, and H3 resolved the contradiction by morphing one into the other at 3:11. Neither `present` setting was right, because the missing statement was a third one: `subject` says **whose shot this is**, is legal only on an instrumental chunk, and is *refused* on a voiced one — the singer owns the frame there, and #58/#59/#60 all say the sentence outranks any field that argues otherwise. Emitted by the beats stage, which knows whose beat it is, rather than inferred from pronouns later.
- **A rendered span assumes its content begins at its first frame (#79).** H3 starts the mouth at frame 0 regardless of where in the chunk the voice actually starts, so a chunk prompted with a lyric that begins seconds in is out of phase for its whole length — 3.30 s on chunk 38, and 4.07 s on chunk 20, which no viewer report had ever named. The metric is the **leading vocal offset**: the start of the first word the chunk is actually prompted with (the same word-midpoint rule `_text_within` uses — factored out, not reimplemented) minus the chunk's start. Note the issue's own proposal ("a chunk start falling in a gap") does not cover its own headline example: chunks 38 and 27 start *inside* a preceding segment. The preference is a **local, zero-cascade** transfer of whole grid steps across one boundary — grow the predecessor by exactly what the chunk shrinks by — so total length, contiguity and every other boundary are invariant by construction, which is what makes it safe where #70's filler-tiling bias was not. Measured over 80 chunks: offsets >1 s went 6 → 4, >3 s went 2 → 0, chunk count and track end unchanged. It is a *preference*: chunk 41 could not move (already at the 124-frame floor, predecessor had one step), and the report names whatever survives.
- **A property that must CHANGE across the video cannot live in a field composed identically into every prompt (#78, #73).** `setting` named "medieval hosts, industrial armies, and nuclear glow all visible" in all 80 prompts, so the 17 chunks authored as an emptied planet were each also told the armies were in shot — a viewer: "the world looks back-to-normal after that." `location` was authored per chunk, validated, and never composed; substituted INTO the existing #32-hardened "Location continuity" sentence rather than appended alongside it, because #73 already established there is no negative-conditioning channel for a second sentence to retract nouns the first one named — `setting`/`location` both unset still renders byte-identically to before. Fixed in commit 888b6d3; verified on pixels — chunk 71, authored as a bare eroded hill, rendered a burning medieval town before, a bare hill under an empty grey sky after.
- **A conditioning signal outranks the prompt describing it.** `LoadAudio.inputs.audio` feeds every chunk's own stem as H3's lip-sync conditioning with no instrumental special case, so an instrumental chunk gets full-level music at the same level as a sung one. Measured on the v8 render: chunk 30 (instrumental, viewer-reported mouth moving at 3:14) sat at −15.2 dB mean against a *sung* chunk's −16.8 dB. Rewording the instrumental clause (888b6d3, itself a real #73 prohibition fix) reduced the mouthing and could not remove it — it was arguing with the audio, not the words. `instrumental_audio_gain_db` (commit fafa6ef) attenuates the stem on instrumental chunks only, is refused if positive at load, and is recorded in `ChunkFingerprint`'s conditioning tier beside `conditioning_source` — which is blind to level and would let `--resume` reuse a full-level chunk inside a silenced run and hand the comparison its control twice. **Unverified against a render** — the card was occupied when it shipped; prove it on an `--only-chunks` slice before trusting it at scale.
- **100% line coverage said nothing about the guarantee it was supposed to prove.** `authoring/worldstate.py` (an event-sourced world-timeline prototype, not yet wired into the render path) shipped at 100% coverage with irreversibility not actually durable: `irreversible` was read off a fact's current row to reject a contradiction and then discarded, so a legal same-value restatement silently un-froze the key and the next write contradicted it — the exact defect the module exists to catch, through its own public API, and the test suite never ran the three-call sequence that finds it. Two more defects of the same shape: `from_dict` validated nothing, so a payload with two simultaneously-open rows for one key, or a closed irreversible row followed by a different value, both loaded silently; and `destroyed_at_t` duplicated the existence fact with nothing keeping the two in step, so editing the entity row alone could resurrect something the fact log still called destroyed. All three reached the bug through restatement or loading rather than the write path, which is where the guarantee was actually claimed — precisely where a line-coverage number can't see. Fixed in commit 2ebfdb7.
- **The fixed world-state module, run over the real 80-chunk plan: 3 real contradictions, 0 false positives.** 4 entities (island, mill wheel, mountain, the war), facts anchored from the concept's own `reading`/`locations` and the beats' own act structure. Beyond the known chunk 62 mill-wheel calibration case, `check_claim` fired on chunk 59 ("a low dark island holds firm along the horizon…") against the island's own destroyed-at-386.0s fact — the same chunk's own lyric says "Now the island is no longer," so under this project's "lyrics are immutable truth" rule the lyric wins and the shot line is the bug — and on chunk 73 ("…as the war goes on in the valley below"), the one chunk in an otherwise-consistent aftermath act that contradicts it; grep confirms "war" appears in no other of the 80 shot lines, so this isn't a keyword firing broadly. Every vocabulary choice that risked a false positive was excluded *before* running by grep-checking it against the real corpus first — "whole" is adverbial at chunk 60 ("swallows the island whole") and chunk 54 ("The whole mountain slope goes white"), not a state claim, and was dropped from both entities' vocabularies pre-emptively.
- **A desync instrument built to test the F25 `present`-hypothesis failed, and the hypothesis failed with it.** Scored on mouth-crop motion vs. same-window audio RMS (no time shift) across 36 of 41 scoreable voiced chunks: only 3 of the 7 chunks a viewer flagged as desynced scored worse than the corpus median, and chunk 41 — the one chunk with independent ground truth, #79's own measured 1.607 s leading-vocal-offset — ranked 33rd of 36, among the *most*-synced-looking. Cause, predicted before running rather than discovered after: every fingerprint's `conditioning_source` is `"mix"`, not an isolated vocal, so chunk 41's RMS trace is continuous with no dip where the voice is actually silent — the confound the instrument's own docstring warned about, landing exactly as predicted. Re-scoring F25's `present`-second-character hypothesis against what actually rendered (`run_state.json`'s fingerprint, not the raw plan field, which counts a chunk's own singer as `present` and inflated the quoted base rate to 71%/46%) gives 2/7 = 29% against a corrected 29% base rate — exact parity, zero support. Recorded as two failures, not retried past the number: an instrument that cannot rank the one chunk it can check against a mechanism cannot be trusted to rank the other 34, and a hypothesis is not rescued by fixing its own measurement bug.

## Two compute paths, billed differently

- **The render is local.** `music-video-maker` drives a ComfyUI you host on your own GPU and contains no model calls at all. It needs no API key and will not use one that happens to be in the environment. What a run costs is GPU hours and electricity.
- **`mvm-author` shells out to the `claude` CLI**, so whatever that CLI is authenticated with is what pays — a subscription (no per-run charge) or an API key (billed per token). The project runs the binary on PATH and neither knows nor chooses.
- **`cost_usd` in `.authoring/session.json` is a token valuation, not an invoice.** It comes straight from the CLI's JSON envelope (`driver.py`, `None` rather than a guess when absent) and is priced at API list rates. On a subscription nothing is billed per run. Read it as *relative effort* between stages — beats is roughly twice concept, a revision round is not free — never as what a video cost. Quoting these as money spent misleads anyone without metered API access, which is most people running this.

## Non-negotiable invariants

- **Lyrics are immutable truth.** Forced alignment only — never ASR transcription of the vocals.
- **The master audio track is the only audio in the final video.** Generated audio is always discarded; sync comes from alignment timestamps, not generated sound.
- **Never hardcode ComfyUI node IDs.** Locate nodes by `class_type` (plus title disambiguation) via graph introspection; user edits on the canvas renumber IDs.
- **No sleep-polling.** Execution tracking is event-driven over the WebSocket; completion = `executing` message with `node == null` and matching `prompt_id`.
- **One chunk failing must not kill the run.** Resilience state machine: watchdog timeout → `POST /interrupt` → `POST /free` → bounded retry → dead-letter queue; runs are resumable.
- **The chunk timeline must cover the whole track.** Rendering only voiced spans looks fine per chunk and is silently broken: Stage 5 concats end to end, so every skipped instrumental is squeezed out of the video while the muxed master keeps it. A typical song is under half vocals. `instrumental_coverage` (default on) fills the gaps and re-anchors every chunk so video offset == audio offset by construction. This includes the zero-segment case — a wholly unvoiced track, or a voiced one authored with nobody ever shown singing (an empty `lyrics_file`) — which `slice_audio` tiles as filler across the *entire* track rather than the pre-2026-08-12 behavior of returning no chunks at all.
- **A resumed chunk must prove it belongs.** "The mp4 exists" is not "the mp4 is
  the right mp4". Every `ChunkResult` records a `ChunkFingerprint` (span, frame
  count, resolution, prompt hash, character, reference photo) and `--resume`
  compares it; a chunk whose span moved is re-rendered, because reusing it
  assembles a desynced video with no error anywhere. Editing the lyrics file is
  enough to trigger this. `run_state.json` carries a `schema_version` so a file
  written before fingerprints existed is rejected, not misread.
- **A property that must hold across the whole video needs its own field.** Stated in forty places, it drifts: geography wandered between countries until `setting` existed, and presentation direction smuggled into `role` is what made the performer sing through every instrumental, because `role` is injected into every chunk. `setting`, `global_appearance` and `CastMember.appearance` compose into every prompt. Adding free text to an existing field to carry a new *kind* of statement is how that bug recurs.
- **On the chained path, the seed frame IS the identity conditioning.** `MiniMaxH3ImageToVideo` has no `ref_images` input at all, so a chained chunk's likeness comes entirely from the predecessor's final frame. A frame showing the back of the performer's head carries *nothing*, and the model invents a face when she turns round — 7 of 12 chained seeds in one real run were like that, because `i2v_chain_scope = "instrumental"` chains exactly the walking shots. Face-presence is a precondition for chaining (`i2v_require_seed_face`), not an assumption; `i2v_reanchor_interval` is only a positional guess at accumulated drift. Detection is not recognition — a large face belonging to someone else still passes (#47, #49). Recognition now exists (SFace cosine similarity against the cast member's own reference photo, floor 0.34, calibrated on 16 real pairs: worst genuine 0.353, strongest impostor 0.208 — see `docs/seed-face-recognition.md`) but is **opt-in**, because the weights are 38.7 MB and deliberately uncommitted, and defaulting it on would silently refuse every chain in every existing config. The two failure modes are split on which mistake is cheap: recognition *requested* with the model missing refuses loudly at config-load, while a frame that merely cannot be judged degrades to the base path, which is the better-conditioned one anyway.
- **Chained rendering makes every per-chunk instruction a recurrence relation.** Three bugs in one week came from this: `last_frame` correct as a keyframe and catastrophic as the next chunk's seed (#44); `appearance` correct against a photo and compounding against its own output (#46); a seed frame assumed to contain the thing it conditions (#47). Before adding any prompt component or graph input, ask what it does on the *fifth* application to its own output. Anything relative — anything that displaces rather than specifies — will drift.
- **A guard's threshold belongs near the evidence, on the side whose mistake is cheap.** #47's confidence floor shipped at 0.6 justified as "well clear" of detections scoring ≥0.835 — backwards, since a false-positive guard set *below* the evidence is exposure, not margin. It passed a blank office wall at 0.669 and cost a shot. Ask which error is cheap: refusing a chain costs a better-conditioned base-path shot, approving a bad one costs the likeness.
- **The GPU can be taken from under a running render.** The custody pre-flight is point-in-time; `ResilientRunner` re-reads free VRAM before every chunk it submits and stops the run cleanly below the floor, because H3 staging onto a contended card can go silent instead of raising CUDA OOM and wedge the host. A failed chunk is cheap; a power cycle that lands in Windows is not.
- **No LLM in the render path.** `prompting.py` is pure string composition. Per-chunk narrative direction comes from an authored `shot_plan.toml` written once and committed as data — never an inference call at render time, which would break determinism, `--resume`, and the no-metered-API rule. The sanctioned exception lives entirely outside the render path: `music_video_maker/authoring/` (issue #54) calls a model, once per song, by hand, and writes a file a human commits — see "Authoring layer" above. `tests/test_authoring_boundary.py` enforces the boundary between the two, not just this sentence.

## Everything committed here is intended to become public (#51)

This repo is a candidate for open sourcing. Both blockers found in the
2026-08-12 audit were introduced *the same day*, by changes that felt too small
to think about — a test fixture and a 232 KB model file. Assume anything
committed ships, and check before adding, not before releasing.
`tests/test_repo_assets.py` enforces the first two mechanically.

- **No likenesses of real people without consent.** A rendered H3 frame
  derived from a cast photo depicts a real, identifiable person; publishing it
  is *their* decision, not a repo-hygiene question. #47's regression fixtures
  originally depicted a cast member whose permission to publish had not been
  asked for — resolved 2026-08-14 (#51 §2) by re-rendering the same
  regressions from `storms` with Derek's own likeness instead, since he's both
  the subject and the one publishing the repo. `Asset.__init__` in `test_repo_assets.py` now
  refuses any `depicts_real_person=True` entry with no recorded `consent`. For
  anything new, prefer a synthetic or consented subject — and if only real
  footage proves the bug, keep the test skip-if-absent so the fixture can be
  removed without gutting the suite.
- **Check redistribution before committing a third-party binary** — models,
  weights, fonts, sample media. Record source, licence and sha256 beside it in
  code, the way `faces.py` does for YuNet. "It downloaded fine" is not a
  licence.
- **No credentials, ever.** `.env` is gitignored; keep it that way. Never
  commit a session file, token or key, including inside a test fixture.
- **Internal network detail gets a placeholder.** Tailscale hostnames are fine
  — they are meaningless outside the tailnet. Raw LAN IPs and anything that
  maps the home network are not.
- **Naming doris and the song is fine, and usually better.** A measured
  number is worth more attached to real hardware than sanded into "your GPU".
  What is not fine is a doc where a stranger cannot tell which details are
  essential and which are this setup.
- **This applies to GitHub issues, which are the most-read thing here.**
  Song-specific evidence — timestamps, chunk ids, measured dB, a viewer's own
  words — is *required*: it is what makes a claim checkable instead of an
  assertion, and this project's whole method is that a finding is a
  measurement. But lead with the transferable rule: a **`General form:`** line
  first, and a title shaped "general defect: specific evidence". A stranger
  should be able to tell from one line whether it applies to their song at all.
- **Never design the fix around the example.** #69 was very nearly built as
  "give the concept stage a research tool so it can look up folklore", because
  the song that exposed it is about Koschey the Deathless. The actual defect is
  that the authoring layer is handed the lyrics as text to *stage* and never as
  text to *understand* — which is true of a breakup song with no mythology in
  it at all. A fix scoped to the example helps one song in fifty and looks
  finished, which is the expensive kind of wrong. The example proves the bug;
  it does not define it.
- **Authoring session state stays out too.** `.authoring/` (issue #54) —
  `session.json`, generated stage JSON, and especially `raw/` (full,
  unredacted model replies, which routinely include the whole lyrics file) —
  is a run asset like `output/` and `run.toml`, not project code. It lives in
  `~/mvm-runs/<song>/`, never gets created inside a repo checkout, and is
  gitignored belt-and-braces anyway.

## Performance (measured, not assumed)

- **Resolution is the dominant cost**, not frame count — it scales with latent volume. At 141 frames on the 4090: **864×480 ≈ 3.7 min/chunk**, **1344×768 = 9 m 15 s** (measured). A 4:22 song is ~2.7 h vs ~6.8 h.
- `workflow_api.json` carries ComfyUI's template default of 1344×768. Set `render_width`/`render_height` explicitly; hands-on testing was done at 864×480.
- **VRAM headroom buys no speed.** Freeing 5.4 GB changed the same chunk from 554.72 s → 554.78 s. ComfyUI's startup line `Using async weight offloading with 2 streams` is a capability announcement, *not* memory pressure. Don't chase it.
- SageAttention is **not installed** on doris despite appearing in `recommended_nodes`; ComfyUI runs `pytorch attention`.

## GPU custody protocol (issue #19)

A render run takes **exclusive custody** of the 4090:

- Before rendering: stop the card's other tenants **by hand**, then verify VRAM actually freed. The pipeline does not automate this and deliberately never will — see `custody.py`'s module docstring. The specific commands for this host are operator knowledge, not repo content.
- Hardware profile (#13) therefore assumes the full 24 GB.
- After the run: the pipeline `POST /free`s ComfyUI to unload H3 weights; restarting what you stopped is yours.
- **Release is unconditional** — try/finally around `POST /free`, so a crash, Ctrl-C or dead-lettered run still returns the card.

### Stopping the tenant you know about is NOT sufficient (learned 2026-08-07)

The card has other tenants. Who they are changes over time, so **enumerate them, never assume**:

```bash
nvidia-smi --query-compute-apps=pid,process_name,used_memory --format=csv
systemctl list-timers --all          # anything scheduled can arrive mid-run
```

Current tenants (2026-08-08):

| Consumer | VRAM | Trigger |
|---|---|---|
| Ollama / Qwen (Docker container) | ~15 GB | on demand; `OLLAMA_KEEP_ALIVE` holds it resident |
| a TTS service | ~2.2 GB | always-on service |
| desktop session (Chrome, nautilus, ptyxis) | ~0.5 GB | always |

A stack of four scheduled services — the largest an image model on a 30-minute timer — was retired 2026-08-08, stopped and disabled permanently at Derek's request. It was the biggest scheduled hazard on the card, so a long run is materially safer now. Do not re-enable it to "restore" anything; its absence is deliberate.

That leaves Qwen as the one consumer big enough to matter. It is *on demand*, so a quiet card is not proof of a free card — one request pulls 15 GB back.

**Do not stop the Ollama container to keep it quiet.** Pausing the service that fronts it unloads Qwen from VRAM, which is the sanctioned move; stopping the container takes the endpoint down for *every* consumer and the service then refuses to resume until it can warm the model again. The per-service commands are operator knowledge.

**Failure mode to respect:** when H3 stages its 19995 MB onto a contended card it does not reliably raise CUDA OOM — it can go **silent** mid-load and wedge the host. The process then survives SIGKILL (stuck in a driver call), the modules will not unload, and only a power cycle recovers. Rebooting doris is expensive: the board ignores BootOrder and frequently lands in Windows, needing manual `bcdedit` recovery from another machine. A wedge can strand the box. See #23, #24.

### Kernel upgrades are frozen (2026-08-08)

`apt-daily`/`apt-daily-upgrade` are enabled, but `/etc/apt/apt.conf.d/50unattended-upgrades` now blacklists `linux-image`, `linux-headers`, `linux-generic`, `linux-hwe`, `linux-modules`. Everything else — including `linux-firmware-*` — still patches automatically.

Why: unattended-upgrades installed a kernel (`-28` → `-29`) while the box stayed up. The NVIDIA modules package remained pinned at `-28`, so the *next* reboot, days later, came up with no NVIDIA driver at all — `nvidia-smi` dead, GPU gone, display on a fallback framebuffer. The breakage is armed silently and only fires on reboot, which makes it very easy to blame on whatever was running at the time. It cost an hour of misdirected diagnosis: it presented as "the render killed the GPU."

Updating the kernel is now a deliberate act:

```bash
sudo apt update && sudo apt install linux-generic-hwe-26.04
dkms status          # confirm NVIDIA modules built for the NEW kernel
sudo reboot          # only after dkms looks right
```

Backup of the original config: `/etc/apt/apt.conf.d/50unattended-upgrades.bak-preblacklist`.
